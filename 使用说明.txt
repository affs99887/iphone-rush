iPhone Duo 预约助手 2.0 · 指派员 + 双路操作员 · 独立无头浏览器 · Windows 10/11 x64
公开仓库中的个人资料均为示例，使用前请在设置中填写自己的信息。

一、启动
双击 iPhoneDuo预约助手-2.0.exe。已内置 Chromium，不需要 Edge 或 Python，不弹命令行，也不弹浏览器窗口。只有操作面板、验证码、登录与同意书等必要对话框可见。首次解包浏览器需要数秒。
同一时间只允许运行一个本软件（含旧版 1.x 请先关闭）。

二、这版做了什么（和你最关心的问题）
1. 速度：软件自身开销可忽略，瓶颈只在 Apple 服务器。预购前自动预热会话，开售 T-2 秒发起多入口竞速，选配到加购的点击多在 0.1 秒级完成。
2. 精准可靠：每一步点击都读回官网实际结果再走下一步；订单金额、机型、数量、发票、招行 24 期、收货方式逐项核对；全局只允许提交一次，超时或重启都不会重复下单。
3. 多开：每路默认 3 个购买入口（最多 4 个），首个可用入口接管、关闭其余。
4. 双路并行：门店自取、送货到家各一条独立流程，独立浏览器、购物袋、验证码、设置与防重复记录。一路等验证码/暂停/出错，另一路继续。
5. 无头、不打扰：实测与运行默认用隐身无头浏览器，不动你的鼠标键盘、不占用你的桌面。只有在你主动点“显示浏览器窗口”或需要你接管时才可能可见。
6. 关于 541：旧版无头一访问官网就被 HTTP 541 拦截。已查明这是 Apple 的 Akamai 安全盾时序问题（不是无头被识别），本版先等安全盾握手完成再操作，实测两路无头已稳定走到结账阶段，0 次 541。

四、面板结构
顶部：倒计时（按校准后的官网时间）、主按钮“一键布防 / 停止全部”、“官网试跑”、“设置”。
左侧“指派员”：总状态、下单策略（争取两单 / 只下一单）、提交权归属、浏览器模式（自动 / 无头 / 隐藏窗口）、时钟偏移、健康、时间线。
右侧两张“操作员”卡（自取 / 送货）：状态、六步进度（入口 / 选配 / 购物袋 / 结账 / 核对 / 提交）、入口竞速、选配四项、门店或地址、订单核对、速度小表、页面截图缩略图，以及暂停 / 继续 / 查看页面 / 更多 / 提交已核对订单。
底部可折叠“记录”抽屉：运行记录（已脱敏，不含验证码、卡号或证件号）。

五、使用步骤
1. 在“设置”里核对两路联系人、付款方式、地址、门店、预约时间与结账方式（游客 / 登录账户）。
2. 点“一键布防”：软件预热两路浏览器、校准官网时间，并按开售时间自动开始。也可在每张卡的“更多”里分别预热 / 布防 / 立即开始。
3. 想先演练，点“官网试跑”：用在售 iPhone Air 云白色 1TB + AC+ 走真实官网流程，核对通过后自动提交一张测试订单（会收到邮件，不付款 30 分钟后官网自动取消）。下次试跑会自动清空测试购物袋。
4. 默认全自动：核对页全部项目（商品、收货方式、联系人、发票、招行 24 期、金额上限）核对通过后自动点一次“立即下单”，不再等你点按钮；核对不通过绝不提交。
   不想自动提交时，在“设置”里取消某一路的“自动提交已核对订单”，那一路会停在核对页等你点“提交已核对订单”。付款始终在官网/手机完成。
   提交后官网通常要 20 秒到 1 分多钟（核对页 → “正在处理” → 订单页）。软件会安静等待最多 3 分钟、绝不重复点击；
   看到订单页（“你的订单正在等待付款… 订单 #W…”）即显示“下单成功”和订单号。正式订单请在 30 分钟内用“掌上生活” App 扫码付款。
5. 全程保持电脑和网络可用。合盖、手动休眠、关机或断网会影响任务。

六、验证码、同意书与登录
- 短信验证码：软件点“验证”发送后，会同时弹出 Windows 通知和软件右下角的通知卡，标明是哪一路、发到哪个手机号。
  在 Windows 通知里输入后点“提交验证码”，或在软件通知卡里输满 6 位自动提交，任选其一。验证码只用于当次验证，不写文件或日志。
- 等待输入的通知卡不会自动消失；验证通过后显示“验证通过”约 2.5 秒再自动关闭。任何时候点右上角 × 一次即可关闭。
  若关闭时验证码还没提交，这一路会暂停在验证步骤，点该路卡片上的“重新输入验证码”即可重新弹出。
- 截图记录：每次运行的每个页面、每步操作前的画面及“查看页面”截图都保存在 data\（送货为 data\delivery\）下的
  diagnostics\history\<日期-时间> 文件夹（试跑在 trial-headless\diagnostics\history），附脱敏的页面记录；验证码与登录页面不截图。
  自动保留最近 30 次运行（每路最多约 600 MB）。
- 官网条款：默认自动同意（隐私知情同意书，以及核对页若出现的条款复选框），不再弹窗确认。
  自动勾选两次仍未成功时才请你处理；可在“设置 → 官网条款”关闭，关闭后改为在软件确认框里点“同意”。
- 登录 Apple 账户：若官网强制登录（某些取货路径可能如此），在该路“更多 → 登录 Apple 账户”里输入 Apple ID 与密码，软件在后台页面内登录；两步验证码也在软件内输入。密码只在本次命令的内存中，不写设置、日志或文件。
- 若官网只允许每账户下一单：指派员会切换“同账号顺序下单”，先让已登录的一路完成提交，确认后另一路用同一账号再建一单。

七、首发当天建议
- 提前在“设置”里确认信息并点“一键布防”，让软件预热。
- 准备一个备用网络（如手机热点）。同一 IP 短时间大量请求可能被官网降低信誉；真机实测已observed到这一点。必要时切换网络后重试。
- 取货需携带本人身份证原件，取货人姓名须与证件一致；软件不保存身份证号，官网若出现证件字段会暂停提示你自行填写。

八、故障与恢复
- 遇到安全盾 541、限流（403/429）会退避并在同一会话重试，不盲目刷新重建订单。
- 加购后若官网返回 404 / 购物袋为空，会先核对现有购物袋，确有需要才允许再加购一次（上限 2 次）。
- 任一路长时间无响应，指派员会自动软/硬重启该路浏览器（保留购物袋与防重复记录，有重启上限）。
- 正式订单记录保留在原 data 目录（自取 data、送货 data/delivery）；试跑用各自 trial-headless 子目录，互不干扰。请勿删除 data 目录绕过防重复保护。

九、验证边界（务必知悉）
- 自动化回归 142 项通过，使用真实官网 DOM 回归与故障注入；这只证明程序逻辑，不等于官网下单成功。
- 送货到家一路已在真实官网值守实测到“订单核对页”（立即下单前一步）：送货方式、地址浮层、收货人信息、短信验证、招行 24 期均自动完成，用户只需输入一次短信验证码，0 次 541。注意：这轮是测试脚本直接运行引擎（无界面），由你亲自操作 EXE 的完整验收尚未进行。
